### A test failure found on the fresh clone, and its root cause

The first `pnpm -w test` on the first fresh clone (commit `7b6f7a6`) exited 1: `@fitadapt/legal … matches node:crypto on known vectors and random strings 5275ms — Error: Test timed out in 5000ms`. This is the M20 property test that compares the pure-TS SHA-256 with `node:crypto` over 500 random strings. Alone, with coverage, it takes about 1.3 s; `pnpm -w test` runs all 24 package test tasks in parallel on this 4-core machine, and M06 added CPU-heavy tests of its own (the exercise-library property tests take 3.4 s and 1.5 s under the same load), so the test crossed vitest's 5 s default timeout. This is very likely the unreproduced failure in the M20 PO verification note (one of five runs, package unknown). Fix (`f09023e`): `testTimeout: 30_000` in `packages/legal/vitest.config.ts` and `packages/exercise-library/vitest.config.ts`, the budget `tooling/legal` and `tooling/security` already use. No assertion, run count or property changed. After the fix, the second fresh clone ran `pnpm -w test` four times (two plain, two `--force`) without a failure.

## Deviations from the spec, with reasons

1. **Seed is 152 exercises, not the ≥ 250 launch target.** The MVP seed (≥ 120) is what the goal asks; the launch target needs the CMS workflow (M18) and council review.
2. **Wording lives in `packages/i18n`, not inside the exercise records.** CLAUDE.md rule 5 (all user-facing strings in i18n, FR and EN) is binding, and it puts every cue under the claims linter. Exercises hold keys (`nameKey`, `cueKeys`, `mistakeKeys`). The M18 CMS must edit the catalogues through the same review.
3. **SUBSTITUTES edges are generated by a similarity model**, not hand-scored per pair (ADR-011). The model's weights are config values awaiting review; experts can later override single edges.
4. **"Bodyweight only" includes ordinary surroundings**: floor, wall, door frame, a stair, a stable surface at hip height (table, counter). A sturdy chair, a bench and a box count as equipment. Stated in `src/taxonomy.ts`; to be confirmed by A3.
5. **Coverage is below 100% for bodyweight only (98.0%)**: `farmer_carry`, `suitcase_carry` (no load-free carry) and `prone_floor_pulldown` (the only no-equipment vertical pull, so it has no equal-or-easier bodyweight substitute). Home-basic and full-gym: 100%. Park and travel: 98.7% (carries).
6. **The M02 "inverted row (height-adjusted)" step is two exercises** (`inverted_row_incline`, then `inverted_row`), and "incline (by height)" is two (`incline_push_up_high`, `incline_push_up_low`). The ladder test checks reachability through each M02 step and direct edges within the canonical ladders.
7. **`SafetyProfile` is defined in `packages/shared` by M06** with the M01 fields (`maxRPE`, `allowHIIT`, `allowMaxTests`, `impactCeiling`) plus the two the library needs (`avoidTags`, `excludedExerciseIds`). M01 owns the screening that fills it and must extend this schema, not fork it. The library does not decide which tags a screening outcome implies (seat A1).
8. **Media**: no images, videos or diagrams ship (spec: placeholders only). The publishing gate, the offline packs by equipment profile and low-bandwidth selection exist in code (`src/media.ts`) and are tested with a fictional asset record; no media file was added.
9. **Admin CMS (M18) not built.** The content workflow (versions with content hash, submit, two-person approval by A2 and A3 with distinct reviewers, publish, `content.approved` defensibility payloads) is a pure API in `src/content.ts`; there is no UI and no server storage yet.
10. **Custom exercises**: data layer only (schema, SQLite storage, wipe). No creation form in the app yet. Custom exercises are never offered as substitutes (no reviewed joint-load profile).
11. **The engine does not yet write S2 events.** `substitutionSafetyEvent` returns the `safety.event` payload; the caller (M02/M05 session generator, API `recordSafetyEvent`) writes it with the engine stamp.
12. **Offline copy is installed synchronously at app start** (on first launch or after a content change). Fine for 152 exercises; revisit with the 250+ library on a low-end Android device (M19 performance budget).
13. **Existing tests changed, none removed or loosened:**
    - `tooling/legal/test/legal-tooling.test.ts`: the repository's asset register now has 5 entries (DATA-003 added), so the exact count changed from 4 to 5 (still an exact-equality check).
    - `apps/mobile/__tests__/boot.test.tsx`, `apps/mobile/__tests__/age-gate.e2e.test.tsx`: their route maps gained the new `library` route (the root layout declares it; without it expo-router warns). Assertions unchanged.
    - `apps/mobile/__tests__/app-config.test.ts`: a new `describe` block for the M06 release guard; the M20 cases are unchanged.
14. **Ebben values mapped to seed variants**: "hands elevated 60 cm ≈ 41%" is attached to `incline_push_up_low` (hands on a bench, box or chair seat, typically 40–60 cm) and "feet elevated 60 cm ≈ 74%" to `decline_push_up` (feet on a bench, box or chair). The heights of the seed variants are not fixed at 60 cm, so A5 must confirm or replace these values.
15. **`wipeLocalDatabase`** (M17 account wipe on the device) now also clears favourites and custom exercises when those tables exist; the bundled library stays.
16. **Docker daemon unavailable** (as in M00/M17/M20): `pnpm --filter api test:integration` ran against local PostgreSQL 16 and Redis. **No device or emulator**: the offline library is proven with jest-expo + React Native Testing Library over sql.js (same SQL through Drizzle). No Maestro flow was written (the goal does not ask for one). **CI not executed on GitHub** (not pushed).
