### The runtime output guard (every model text, not only in tests)

A text must pass, in order:

1. Only retrieved ids are cited, and a knowledge answer must cite one.
2. The L1 claims linter.
3. No claim to be a human or a licensed professional (L5).
4. No condition named or suspected.
5. No push through pain or a red flag.
6. No medicine advice.
7. No promise of results.
8. The app's guilt and body-shaming denylists, for the reply's language.
9. Every kg, kcal, %, sets or reps number comes from the engine or the cited content.

A failure is never shown. The user gets a fixed fallback, and an **S6 safety event** is logged. A provider refusal or a cut-off answer is handled the same way.

## Deviations, with reasons

1. **`requestDeload` gives a lighter day, not a deload week.** The engine regenerates today with reduced readiness. A triggered deload week is M05's decision (four triggers) and is not something a chat request should force.
2. **Swap proposals are informational.** The coach shows the engine's replacement, but the swap itself uses the workout screen's own swap, which calls the same engine function. This avoids a second write path into a running session.
3. **Session proposals are proposals.** The device starts them, and the server re-derives them as it does any session. The server writes only the records a tool decided: pain reports, reflows and red flags. It writes them **through the sync server** as if the device had pushed them, so the M05/M08 validators and events apply.
4. **Tiers:** M16 is not built, so everyone is `free` (`coachTierOf` is injectable, and the tests cover premium).
5. **Knowledge content is pending.** All 25 entries need approval before production, and the production start refuses otherwise. Development and tests run with pending content.
6. **Pain reports from chat outside a session have `planId: null`**, like an M05 check-in. Under M05's rule they never clear a red joint.
7. **Consent:** the chat is gated by the `ai_coach` consent. Conversation content is treated as health data (consent-gated, exportable, erased on withdrawal), but no separate health-data consent is asked in the chat.
8. **Voice (M14) and coach KPIs (M18)** are deferred.
9. **The Maestro flow was not executed**: there is no device or emulator here. The journey is covered in jest-expo, and a test checks that the flow's testIDs exist.
10. **Docker is not available.** `test:integration` ran against the PostgreSQL and Redis instances that are already available in this environment.
11. **Past the 70-turn guideline** (see Result).
12. **Existing tests changed, with every assertion kept:**
    - `apps/api/test/integration/auth.test.ts`: the exact list of authenticated paths gains the 3 coach paths.
    - `apps/api/test/integration/privacy.test.ts`: the inventory test adds a coach conversation before the export, so that the new tables are exercised.
    - `apps/api/test/integration/harness.ts`: coach options, and the coach tables are truncated.
    - `apps/mobile/__tests__/routes.tsx`: the coach route is added.
    - `packages/legal/src/m11.test.ts`: `'ai_coach' as const` typing only.
13. **Exports added to existing code:** `storedExecution` in session-hooks; `storedProgram`, `storedReflows` and `latestRows` in program-hooks. They are reused by the context hardening.
14. **Timing tests under load (not changed).** On the working tree, two full `pnpm -w test` runs failed in two tests that M11 does not touch:
    - the engine's 15,000-run `generateSession` property hit its 180 s timeout (it takes 32.7 s alone);
    - M04's "two years of data in < 1 s" measured 1,065 ms.

    The cause: four other agents were running their own test suites in other worktrees on this 4-core machine, with a load average of 13–18. Both tests pass alone, and in the fresh-clone runs below. Neither test was loosened.
