## Deviations from the spec, with reasons

1. **Templates are not committee-authored.** The spec asks for "committee-authored program templates plus auto-generated programs". No council member is seated; the templates in `templates.ts` are the engineer's drafts of the spec's split rules and every program is generated from them. A3 must author or approve them.
2. **Concurrent rule is stricter than "when avoidable".** When the user's chosen days leave no spot for the week's intervals away from the day before a heavy lower-body session, the week keeps steady cardio instead (`program.concurrent.intervals_replaced`); the program never places intervals there. On the default days this never happens.
3. **Volume targets are counted per muscle group**, not per individual muscle: chest, back, shoulders, arms, quads, glutes/hamstrings, core, with fractional counting (a press counts ½ for shoulders and arms; `planned`) and direct sets (`direct`) reported side by side. Short sessions do not reach the target; the week says so (`program.volume.time_limited`) instead of overrunning the session time. The goal's position in the range (e.g. fat loss and health at the minimum, muscle gain at the middle) is an engineering choice.
4. **"Fat loss keeps strength work and adds aerobic volume"**: as strength sessions with a 10-minute cardio finisher (1–4 days) or cardio days on top of 4 upper/lower days (5–6 days). Aerobic minutes are reported per week; the WHO weekly target and HR zones are M03.
5. **Programs start on the Monday on or after the day they are made** (a partial first week would break the weekly volume model); the M07 first session covers the days before. 3 mesocycles per program; after it ends the calendar offers a new one.
6. **One rest day is kept**: 7 training days per week become 6 (`program.schedule.rest_day_kept`).
7. **Training days**: the M01 profile has no weekday choice, so the app uses evenly spread defaults; the engine accepts chosen days (`trainingDays`) and uses them when the rules allow (not exposed in the UI yet).
8. **"Extra session"** is read as a session on a day that was not a planned training day of that week (≤ 1 per week); a reflow never raises the number of sessions in a week. A merged session gets the missed session's primary slots (≤ 2 sets each) as secondary slots within the session time.
9. **Reflow also refuses to create "intervals the day before a heavy lower-body day"** (the concurrent rule applies to reflow too).
10. **`ENGINE_VERSION` not bumped** (as in M07): bumping would change the engine version recorded for M01/M07 events and existing test expectations. Programs carry `rulesVersion` (`PROGRAM_RULES_VERSION = 0.1.0`), which the server also checks. Open question for M19.
11. **Programs and reflows are health collections** (the input embeds the SafetyProfile): health consent required, erased on withdrawal, like M07 assessments.
12. **The server re-derives programs against the latest stored screening and equipment profiles.** If the user re-screens or edits a place after making a program offline, the old program is refused at sync and a new one is needed (open question 4).
13. **KPIs** (adherence ≥ 70 %, reflow acceptance) need the analytics pipeline (M18) and executed-session logs (M02); not measured.
14. **No device / no Docker / CI not run on GitHub** (as before): journeys proven with jest-expo over sql.js; integration tests on local PostgreSQL 16 and Redis. No Maestro flow for M08.
15. **Existing tests changed, no assertion removed or loosened:**
    - `packages/sync/src/test/sync.test.ts`: two new assertions (`programs`, `program_reflows` append-only).
    - `packages/legal/src/release-defensibility-claims.test.ts`: one new assertion in the legal-hold export test (`programs` section empty for the sample) and one new test for the M08 payloads.
    - `apps/mobile/__tests__/routes.tsx` (route map helper, no assertions): the `calendar` route added to `m01Routes`, as M07 did for `assessment`.
    - `packages/engine/vitest.config.ts`: `testTimeout: 30_000` (the budget packages/legal and exercise-library already use) for the whole-program property tests under turbo's parallel load; no assertion or run count changed elsewhere.
    - M07's re-assessment test (`apps/mobile/__tests__/assessment.test.tsx`, 4-week default) is unchanged and still passes: without a program the default applies.
