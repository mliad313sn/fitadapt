## Deviations from the spec, with reasons

1. **Docker daemon unavailable.** `docker compose up -d` could not run here. `docker-compose.yml` is written as specified but was not executed. Integration tests ran against the already-running local PostgreSQL 16.13 and Redis on 127.0.0.1. Tests read `TEST_DATABASE_URL` (or `DATABASE_URL`) and `REDIS_URL` from the environment. The only defaults are in `.env.example`, which the integration config loads when no `.env` exists and which never overrides variables already set. The suite resets the schema, so it refuses to run against a database whose name does not end in `_test`.
2. **No device or emulator.** "The Expo app boots" is shown by the jest-expo router boot test and by a successful `expo export` bundle for Android and iOS. The cold-start budget (< 2.5 s on a ~3 GB Android device) was **not measured**. It needs a reference device and belongs in CI device runs (Maestro, later module).
3. **EAS.** `eas.json` was written but not validated with the EAS CLI (no Expo login). `appVersionSource: remote` and channels assume an EAS project that does not exist yet.
4. **CI not executed on GitHub.** The same commands pass locally (see the table above).
5. **Sentry not installed.** `@sentry/node` 11 depends on the `sentry` CLI under FSL-1.1 (source-available, not open source), which fails the L6 licence gate. The API loads Sentry only if the SDK is installed and `SENTRY_DSN` is set, with PII collection off and events scrubbed. The mobile app has a no-op `reportError` hook. The provider choice needs a licence review (seat B3) or an alternative.
6. **OpenTelemetry.** The API emits spans through `@opentelemetry/api`. No SDK or exporter is registered yet (production infrastructure is M19), so tracing is a no-op today.
7. **sharp excluded** from the install (`ignoredOptionalDependencies`): LGPL-3.0 libvips binaries, optional for Next.js image optimisation, which the stub does not use (`images.unoptimized`).
8. **TypeScript 5.9, not the current `latest` (7.0).** typescript-eslint 8.70 supports `<6.1`, and the Expo/Next toolchains are validated on 5.x (ADR-001).
9. **Tests are exempt from the i18n lint rule** (`*.test.tsx`, `test-utils.tsx`, `__tests__`). They use literal fixture labels and are not shipped UI. All shipped JSX is checked.
10. **API coverage is measured in two runs.** `test` (unit, no services) measures the modules it exercises. `test:integration` runs unit and integration tests and measures all of `apps/api/src` except the two process entry points (`server.ts`, `db/migrate-cli.ts`), with an 80% threshold.
11. **`test:integration` builds the API's workspace dependencies first** (`turbo run build --filter=@fitadapt/api^...`), so it works on a clean clone without a prior `pnpm -w build`.
12. **Sign in with Apple / Google is a stub:** interface plus `501 auth.provider_not_configured`. No credentials exist.
13. **No sign-in UI in the app** (onboarding is M01). The device sync client therefore has no access token; pushes are treated as offline and stay in the outbox. The API sync path is proven by the integration tests.
14. **No mail provider.** The dev server uses an in-memory mailer (codes are never logged), so a developer cannot yet read a code from `pnpm dev`. With `NODE_ENV=production` the server refuses to start rather than drop codes.
15. **Placeholder app identity.** `app.json` uses `name: "Companion (dev)"`, `slug: companion-dev` and bundle id `dev.companion.app`, because "FitAdapt" is a codename that must not appear in store metadata or public assets (L7, C13). Internal package scope `@fitadapt/*` is not public.
16. **CLAUDE.md not modified.** The M00 commands in its Commands section (`pnpm install`, `pnpm dev`, `pnpm -w typecheck|lint|test`, `pnpm --filter api test:integration`) work as written. `pnpm dev` needs `cp .env.example .env` first (the API reads `.env`); on a clean clone it brought up the API (`/health` 200 on :3000, migrations applied), coach-web (200 on :3001) and Metro (200 on :8081). Metro's optional React Native DevTools download failed offline, without effect on the bundler. As for the other commands, on this machine the integration services were local processes rather than docker compose (deviation 1). `pnpm --filter api eval` (M11), `pnpm launch:check` (M19) and `pnpm legal:claims` / `legal:licences` (M20) do not exist yet, as planned.
17. **Local Redis snapshot.** The local Redis here uses the repository as its working directory; its `dump.rdb` was briefly committed and then removed from the (unpushed) history. It is now in `.gitignore`.
18. **Transitive assets and licences.** expo-router bundles the Material Symbols font (Apache-2.0) for its built-in screens. Reviewed licence exceptions are `lightningcss` (MPL-2.0 build tool) and `caniuse-lite` (CC-BY-4.0 data). `node-forge` is dual-licensed and taken under BSD-3-Clause.
