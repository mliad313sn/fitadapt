## Deviations from the spec, with reasons

1. **Docker daemon unavailable.** As in M00, integration tests ran against local PostgreSQL 16 and Redis. `docker-compose.yml` is unchanged and still correct.
2. **No device or emulator.** The age-gate "E2E" runs in jest-expo through the real root layout, expo-router and SQLite (sql.js). The same flow is written for Maestro (`apps/mobile/e2e/age-gate.yaml`) but was not executed.
3. **CI not executed on GitHub** (not pushed). Every command of the new job passes locally on a clean clone.
4. **Existing tests changed, none removed or loosened:**
   - `apps/mobile/__tests__/boot.test.tsx`: the app now opens on the S7 age gate, so the test adds the `age-gate` and `privacy` routes and passes the gate as an adult before its unchanged assertions (home header, pathname `/`).
   - `apps/api/test/integration/auth.test.ts`: the exact list of OpenAPI paths now includes the four new paths (still an exact-equality check).
   - `apps/api/test/integration/harness.ts` (helper): truncates the new tables and accepts optional backup catalogue, analytics sink, consent policies and withdrawal handlers.
5. **Age gate lives in `packages/safety`**, not in M17's own package: it is part of S7, a safety invariant, so it is a constant with property tests rather than configuration.
6. **Consent wording not written** (M20 owns it). M17 ships the data model (version, `documentKey`) and UI labels only.
7. **Export and deletion in the app are disabled until sign-in exists (M01).** The API endpoints work and are covered by integration tests; the mobile client is covered with a fake. The device consent ledger is not yet sent to the server (needs sign-in).
8. **No server-side age check.** The server holds no date of birth until the M01 profile; the gate is on the device.
9. **Correction** covers locale and units; email change needs a verified-code flow (M01). Synced records are corrected by sync (set logs by new entries).
10. **Export on the device** goes through the system share sheet as JSON text, not as a file (a file would need expo-file-system and expo-sharing; not worth two dependencies before sign-in exists).
11. **Encryption at rest on the device and photo encryption / E2E backup are designed (ADR-006), not built**: no health data is stored on the device yet and no photo feature exists (M01, M04). Server encryption at rest, TLS termination and KMS need production infrastructure (M19).
12. **SAST tool**: eslint-plugin-security plus core injection rules, not CodeQL or Semgrep (licence and availability reasons in ADR-007). SAST scope excludes tests and test-runner configs.
13. **Secret-scan false positive in history**: commit `04b42e4` contains a fabricated JWT-shaped test fixture. History is not rewritten; the finding is ignored by fingerprint in `.gitleaksignore` with the reason, and the test now builds the token at runtime.
14. **`pino` declared as an API dependency** (it was already installed through Fastify) to reach its child-bindings symbol for scrubbing.
15. **API 500 logs** now carry the error type and code, no longer the message (messages can quote user input).
16. **Retention of inactive accounts** is scheduled in config but not built (needs the mail provider for a prior notice).
17. **Unrelated commit on the branch**: `9f1497b docs(pmo): Meridian PR #14 merged (5.9.1); DF-01..08 closed` appeared on this branch at 16:31 during the run. It was not made by this run (M17 does not touch `pmo/`) and was left as is.

## Open questions

2. **Pseudonymous records after deletion**: lawful basis and period for `audit_entries` and `data_requests` (L11 vs erasure). (B1, B2)
3. **Minimum age**: is 16 enough in every launch market, and is self-declaration acceptable age assurance? Reinstalling the app resets the gate. (B1)
4. **Senegal**: which CDP formality applies to health data and to hosting in the EU? (Senegalese counsel)
5. **Hosting region and processors** (hosting, email, AI provider, analytics store) and their data-processing agreements. (PO, B1)
6. **Step-up re-authentication** before deletion and export: fresh one-time code, or a recent-sign-in window (a new threshold)? (PE-11, M01)
7. **SAST depth**: add CodeQL if the repository becomes public or GitHub Advanced Security is bought; review Semgrep's rules licence. (B3)
8. **Consent labels**: M20 to confirm the FR/EN labels and descriptions in `packages/i18n` align with the consent texts it writes.
